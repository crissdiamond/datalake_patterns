# Draft Cover Note to Suppliers

Subject: Clarification of UCL ask - reusable Data Lake / Fabric patterns

Hi [Supplier],

Following our recent conversations, I wanted to clarify the ask around the Data Lake / Fabric patterns work.

The outcome we are looking for is not generic Fabric consultancy or additional delivery capacity. We are trying to create for the Data Lake space the same type of reusable architecture approach that we previously established for Integration.

In Integration, the approach allowed Solution Architects to safely design integration flows without needing deep integration engineering knowledge. It also allowed developers to implement those designs through centrally managed reusable building blocks, including EASIKit, Python libraries and Terraform modules.

We would like to explore whether the same model can be applied to the Data Lake / Microsoft Fabric space.

The goal is to create:

- a clear Data Lake pattern catalogue;
- a Data Lake molecule catalogue;
- a safe design language for Solution Architects;
- a mapping from high-level design patterns to low-level Fabric/Purview implementation;
- centrally managed reusable implementation assets;
- a model that enables federated delivery teams to work safely within central guardrails;
- embedded governance, ownership, glossary, lineage, data quality, access and operational controls.

In practical terms, we want Solution Architects to be able to design end-to-end use cases using patterns and molecules, while federated users and delivery teams use centrally approved building blocks rather than building bespoke pipelines and models from scratch.

I have attached a short pack that describes the model, the expected supplier contribution, a draft molecule catalogue, example patterns, delivery expectations and a response template.

Could you please review the pack and refine your proposal against this ask, making clear:

- how you would structure the work;
- what artefacts you would deliver;
- which patterns you would produce first;
- how you would map high-level patterns to Fabric/Purview implementation;
- what reusable implementation assets you would create, recommend or blueprint;
- how you would support knowledge transfer and ongoing UCL ownership.

It would also be helpful if you could clearly separate what is included from what is excluded, particularly around production implementation versus pattern definition, prototyping and reusable asset design.

Kind regards,

Cristiano
